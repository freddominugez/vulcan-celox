# Detailed usage guide

> Screen by screen, with more detail than the [manual](user-guide.md). It was the README until version 0.9.0.

**Full manual:** [`user-guide.md`](user-guide.md), with screenshots. It is the same content as the app's **Help** screen (⌘? or the ? button at the top of each screen). On first launch, the **Home** screen shows a four-step guide that checks itself.

**Sidebar.** Home, Overview, Terminals, Node projects, Tasks, Sticky notes, Tags, Index, Lerd (with its state) and Debug; in the **Agents** group, Agents, Agent history, Branches and worktrees, Usage and cost and Prompts. Below, the collapsible **Sessions** section, with the **Open** terminals and the **History** folder (menu ⋯ or right click on each session: Rename, Add sticky note, Add task and Delete, which sends the memory to the Trash) (finished sessions in subfolders by day: Today, Yesterday and dates, with Load more): each session opens to show its tasks, sticky notes and tags, and clicking any item shows it in the area on the right, highlighted. Then the Lerd sites (also collapsible) with state, open terminals and completed/total tasks, and the Node projects. At the bottom, the Lerd state (a click opens its dashboard).

**Top bar.** Where you are, search (⌘K) and the environment state (`Lerd · nginx ok · .test ok · PHP 8.5`) with Start, Stop and Restart.

**Lerd together with the app.** When Vulcan Celox opens and Lerd is stopped, it starts in the background (the bar shows `starting…` and tells you when it finishes or if it fails, with Try again). The lightning button next to Restart, or the ⌘K search, turns this behavior on and off; `VULCAN_AUTOSTART=0` turns it off through the environment.

**Site.** Header with PHP, Node and HTTPS, the site link and folder, and the actions Open site, Tinker (when there is an `artisan`), Finder, Editor and **New terminal**. Right below is the sessions bar (one tab per terminal) and, in the header, the tabs **Terminal · Tasks · Sticky notes · Tags**, which always act on the selected session:
- **Terminal:** the bar shows only the open terminals; finished sessions open from History with the notice "History · session". When you open a new terminal, the **Open terminal in** window asks for the folder (it suggests the site's, validates what you type, lists recent folders and has **Choose…** with the macOS picker); quick commands such as Tinker open straight in the site folder. A real zsh, with colors, vim and tinker. Several tabs (⌘1 to ⌘9 in the browser), double click renames, **Split** shows two side by side, **Detach** (⇧⌘D) opens the same session in its own window. With no terminal open, there are shortcuts for `git status`, `composer install`, `php artisan about` and `npm run dev`. Terminals keep running when you switch screens.
- **Tasks:** a mini manager with **assignee** and **due date** (Overdue, Today, Tomorrow), a clickable summary (overdue, due today, unassigned), filters by assignee and due date, and the **List** and **Board** views (To do, Doing, Done; dragging changes the status). Tasks created here are linked to the session; the **This session / Whole site** selector shows only the session's tasks or all of the site's (with the session name on each row). Title and Enter; priority, due date and tags on the same line. Clicking the circle advances the status, clicking the priority changes it, double click edits the title, and deleting has Undo. Filters Open/All/Completed, by tag, and sorting.
- **Sticky notes:** linked to the session, with the same scope selector; they save by themselves, with color, pinning, tags and drag to reorder.
- **Tags:** the session's own tags and its tasks and sticky notes grouped by tag.

**Agents panel.** Reads the sessions that Claude Code (`~/.claude`) and Codex (`~/.codex`) write to disk, with no API key and without writing to those folders; it refreshes by itself every few seconds.
- **Code:** a project's whole tree and what is being written to disk, live, with no session needed. Read only.
- **Agents:** cards per session with project, branch, request, files, commands and the publishing trail (edited, commit, push, PR); filters by agent, active, not published and project. The session opens with the tabs Summary, Files, Commands and Timeline, a **possible loop** alert (the same test 3 times with no commit) with the exit prompt to copy, **Resume in a tab** (`claude --resume` or `codex resume` in the session's folder and theme) and **Create task**.
- **Agent history:** both agents together, search as you type across requests, answers, commands and files (ignores accents), results by day. The index keeps what Claude deletes after 30 days.
- **Usage and cost:** tokens and estimated cost by day (bars per agent), project, model and session, over 7, 30 or 90 days, with CSV. The cost is an estimate at API prices (table checked against the official pages, editable in `precos.json` in the data folder); a subscription bills differently. The agent session shows its own cost; `--doctor` shows the last 30 days.
- **Project harness:** a Harness tab on each site, with the contract, the item bar (done, in progress, blocked, pending), the next item, the last green commit and the handoff, for this repository's format (`.harness/`) and the minimal Harness Vulcan format (`.vulcan/`). In a project without a harness, **Install harness** shows the files first and never overwrites (in an existing `CLAUDE.md` or `AGENTS.md` only a marked block is added); **New contract** creates `.vulcan/tasks/<id>.md` with approval pending.
- **Branches and worktrees:** cross-checks the sessions with real git (read only): no commit, not pushed, no upstream, PR open, idle worktree or no session, with the reconciliation prompt to copy.
- **Prompts (⌘⇧P):** buttons by category (Behavior, Parameters, Security, Publishing, Tests and the ones you create); click a card to open the composer with its fields and preview, already filled in with project, branch, base, session, agent and folder, then send it to the terminal as a paste, without Enter, or copy it. Global `.md` files in `~/Library/Application Support/VulcanCelox/prompts/` and per project in `<project>/.vulcan/prompts/` (created only with confirmation; the project one wins over the global). Pinned prompts also appear as buttons above the terminal.
- **Current session:** a button in the top bar; prompts use its data. Default: the most recent one; one click switches; focusing a paired tab switches to its session.
- **Themes and pairing:** each tab can have a theme (Homebrew, Classic, Ocean, Slate, in rotation); the agent session started in it becomes **paired** and gets the same color, by folder and time or, exactly, through the optional Claude Code hook (`--instalar-hook`, see [`instalar-hook.md`](pairing-hook.md), in Portuguese). The agent appears in the session tree, in the `.md` memory, in `INDICE.md` and in the AI documentation text.
- **New terminal (⌘T):** the **Open terminal in** window gains the agent to start (Claude Code, Codex or just the shell) and the theme, already set to the next one in the rotation; with **Don't ask for the folder**, the button opens straight away. ⇧⌘T always shows the window.
- **Bottom panel (⌘J):** on screens without a terminal, the terminal tabs sit in a panel at the bottom, with a draggable, remembered height; ⌘T there opens the terminal in the panel. On site and Terminals screens the panel stays hidden, and ⌘J says so. ⇧⌘D detaches the active terminal into a window. On the Code screen, ⌘F searches the open file. In any terminal: **Split** into two columns, **⌘F** search with "n of m", **Copy output** and WebGL drawing.
- **Collapsed sidebar (⌘B):** only the icons, in a 48 px rail; Sessions, Sites and Node projects open in a menu. Under a 1000 px window, with no choice saved, it starts that way.


**Session memory.** Each terminal is a registered session: typed commands, tasks, sticky notes and tags. When the terminal closes (or the process exits, or the app closes) the memory is written to `sessoes/<site or global>/<date>-<name>-<id>.md`, and rewritten when a linked item changes. If a process is still running, the app asks before closing. Finished sessions stay in **History** in the sessions bar: they open the memory in read mode, and the Tasks, Sticky notes and Tags tabs stay editable.

**AI documentation.** Add an Anthropic key in Settings (it stays in the macOS Keychain and never appears in the interface or in a file) and choose the model. **Document with AI**, in a session's memory, in the open terminal's bar or in the Index screen's list, reads the session (commands, terminal output, tasks, sticky notes and tags) and writes `<memory>.doc.md` with a summary, steps, commands, problems and next steps; the memory gains a Memory/Documentation toggle. **Generate general documentation** writes `DOCUMENTACAO.md` per site (timeline, decisions, pending items and recurring commands). Before anything is sent, a dialog shows the size of the text and how many secrets were masked (keys, tokens, passwords in variables and URLs, private keys); nothing goes to Anthropic without that click.

**General index `INDICE.md`.** Gathers all sessions by site (date, duration, commands, tasks, sticky notes, tags and a link to each memory) and points to `TAREFAS.md`. Opens with the **General index** button in the Overview, which also lists the **Recent sessions**.

**Global Terminals, Tasks and Sticky notes.** The same tools outside a site: all sessions (with the same tabs), all tasks (with site and session) and sticky notes without a project.

**Tags.** Create, rename, change color, see how many items use each one and the progress of the tag's tasks.

**⌘K search.** Actions (new terminal, start environment), screens, sites and terminals per site, tasks, sticky notes and tags.

**Index `TAREFAS.md`.** Always up to date in `~/Library/Application Support/VulcanCelox/TAREFAS.md`, and optionally inside each project's folder (only between the markers `<!-- vulcan:tarefas:inicio -->` and `<!-- vulcan:tarefas:fim -->`).

**To make a project appear:** `cd project-folder && lerd link`. **Diagnostics without a window:** `"~/Applications/Vulcan Celox.app/Contents/MacOS/vulcan-celox" --snapshot /tmp/screen.png` or `python3 -m vulcan_celox --doctor` (includes the `agents` block). **Agent index:** `--reindexar-agentes` rebuilds from scratch; `--podar-agentes 180` deletes events of sessions idle for more than 180 days, keeping the summary.

**Security.** The interface server listens only on `127.0.0.1`, on a random port, and requires a token generated each time the app opens; it never appears on the command line or in the terminals' environment.
