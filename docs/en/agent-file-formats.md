# Claude Code and Codex JSONL formats

Reference for the parser in `vulcan_terminal/core/agents/`. Basis: reading real files on 2026-10-30 (Claude Code with `api-request-blob`, Codex CLI 0.166.0). These formats are private to each tool and change without notice, which is why reading is tolerant. **When the real file differs from this document, the real file wins**, and the parser and this document change in the same commit.

General rule: the app only reads. It never writes to `~/.claude`, `~/.codex`, `~/.claude.json` or `~/.codex/config.toml`. The only exception is the command described in [pairing-hook.md](pairing-hook.md), run by the user.

## Where they are

| Agent | Path | Variable |
|-------|------|----------|
| Claude Code | `~/.claude/projects/*/*.jsonl` | `CLAUDE_CONFIG_DIR` |
| Claude Code subagents | `agent-*.jsonl` and `<session-id>/subagents/*.jsonl`: counted for the parent session, not a session of their own | |
| Codex | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`, `archived_sessions/` | `CODEX_HOME` (comma separated) |
| Codex compressed | `*.jsonl.zst`, through the `zstd` command | `VULCAN_ZSTD_BIN` |

## Reading rules

- Always stream, line by line (`open(path, "rb")`), never the whole file. The app keeps a byte offset and continues from it on the next read.
- Only lines ending in a newline count. A cut last line, while the session is writing, waits for the next read.
- Invalid JSON, a value that is not an object and a line above 5 MB are dropped and recorded in `parse_errors`, and reading continues. The same goes for a line that makes the reader fail.
- A file that shrank restarts from zero.
- Unknown line types are ignored without error.
- A session is active when the file changed less than 90 seconds ago **and** its last event is less than 10 minutes old. The second condition exists because copying a folder changes file dates but not event dates.

## 1. Claude Code

### 1.1 Where they are

- `$CLAUDE_CONFIG_DIR/projects/<slug>/<session-id>.jsonl`, or `~/.claude/projects/...` without the variable.
- Slug: the absolute path of the working directory with every non-alphanumeric character replaced by `-`. `/Users/dev/project` becomes `-Users-dev-project`. Worktrees in `.claude/worktrees/x` get their own folder ending in `--claude-worktrees-x`.
- Next to the file there can be a `<session-id>/` folder with `subagents/` and `tool-results/`.
- Claude Code deletes sessions older than 30 days by default (`cleanupPeriodDays` in `~/.claude/settings.json`). The app's index keeps the summary beyond that.

### 1.2 Lines that matter

| `type` | Use |
|--------|-----|
| `user` with text `message.content` | User request (a turn). Ignore `isMeta: true`, `isSidechain: true` and text starting with `<command-name>`, `<command-message>`, `<command-args>`, `<local-command-`, `<system-reminder>`, `Caveat:` or `[Request interrupted` |
| `user` with list `content` | `text` blocks count as a request; `tool_result` blocks are only tool results |
| `assistant` | `message.model`, `message.id`, `message.usage`, `message.content[]` with `text`, `thinking`, `tool_use` (`id`, `name`, `input`) |
| `ai-title` | `aiTitle`: session title generated by Claude Code itself |
| `api-request-blob`, `api-request`, `api-request-shape` | Copy of what was sent to the API. **Ignore**: they repeat messages and tools and would double the counts |
| `attachment`, `system`, `mode`, `permission-mode`, `last-prompt`, `queue-operation`, `file-history-snapshot`, `file-history-delta`, `tools-used`, `atis-latch` | Ignore |

Common fields on `user` and `assistant` lines: `uuid`, `parentUuid`, `sessionId`, `timestamp` (ISO 8601), `cwd`, `gitBranch`, `version`, `isSidechain`.

### 1.3 Parsing rules

- Tokens: one API turn is written as several `assistant` lines, one per block, all with the same `usage`. Deduplicate by `message.id`.
- Cache: `cache_creation_input_tokens` is the total written, and `cache_creation.ephemeral_1h_input_tokens` separates the 1 hour part; the rest is 5 minutes. The `<synthetic>` model is a message from Claude Code itself and stays out of usage.
- `isSidechain` lines count as activity (their date), not as session content.
- Files: `tool_use` with `name` `Edit`, `MultiEdit`, `NotebookEdit` (edit), `Write` (new, or edit if the file already appeared in the session), `Read`, `NotebookRead` (read). Path in `input.file_path` or `input.notebook_path`.
- Commands: `Bash` (`input.command`).
- Publication: a heuristic on `git commit`, `git push` and `gh pr create` commands. The rules live in a table in `core/agents/rules.py`, not in scattered `if`s. A publication command counts only when its `tool_result` did not come back with `is_error`. Each step needs the previous one since the last edit: a push needs a commit, and a PR needs a push.

## 2. Codex CLI

### 2.1 Where they are

- `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-YYYY-MM-DDTHH-MM-SS-<uuid>.jsonl` and `$CODEX_HOME/archived_sessions/`. `CODEX_HOME` can be a comma separated list; without the variable, `~/.codex`.
- `.jsonl.zst` (compressed) files are streamed through the `zstd` command, always from the start. The app looks for the command in `PATH` and in `/opt/homebrew/bin`, `/usr/local/bin` and `/usr/bin`; `VULCAN_ZSTD_BIN` picks another one, and empty turns it off. Without the command they are ignored and counted in `--doctor`. With the same rollout in both forms, the `.jsonl` wins.
- There is no folder per project: the project comes from the `cwd` of the first line.

### 2.2 Envelope

`{timestamp, ordinal, type, payload}`. `ordinal` is monotonic.

| `type` / `payload.type` | Use |
|-------------------------|-----|
| `session_meta` (first line) | `payload.id` (used in `codex resume`), `timestamp`, `cwd`, `cli_version`, `originator`, `source`. The origin separates tab sessions from subagents and the desktop app. Git (`git.branch` or `git_branch`) when present; **0.166.0 does not send it**, so the session has no branch and the app uses read-only `git` when building the repositories view and the prompt context. A resumed session can have a second `session_meta`: the first one wins |
| `turn_context` | `model`, `cwd` |
| `event_msg` / `item_completed` | **Main source in 0.166.0**. `payload.item.type`: `UserMessage` (request, `content[].text`), `AgentMessage` (reply), `CommandExecution` (`parsed_cmd[].cmd` or `command[]`, `cwd` as a `file://` URL, `exit_code`), `FileChange` (`changes`: path to `{type: add, update, delete, move_path}`) |
| `event_msg` / `user_message`, `agent_message` | Request and reply in earlier versions. The same request can also arrive as `UserMessage`: it counts once |
| `event_msg` / `token_count` | Accumulated `info.total_token_usage`: `input_tokens`, `cached_input_tokens`, `output_tokens`, `cache_write_input_tokens`, `reasoning_output_tokens` |
| `response_item` / `function_call`, `custom_tool_call` | Earlier versions: `apply_patch` (lines `*** Add File:`, `*** Update File:`, `*** Delete File:`, `*** Move to:`), `shell`, `exec_command`, `container.exec`, `local_shell` (`arguments.command` as a list or text). In 0.166.0 the tool is called `exec` and carries JavaScript code: ignore it, `item_completed` already records commands and files |
| `response_item` / `message` with `role: user` | Only as a fallback when there is no `UserMessage` or `user_message`; ignore text starting with `<` or `#` (injected context) |
| `token_usage_record`, `world_state`, `compacted`, `reasoning`, others | Ignore |

Tokens: `input_tokens` includes cached ones, so input is `input_tokens` minus `cached_input_tokens`. The total is accumulated: each event's consumption is the difference from the previous one, and a smaller total restarts the count from there.

Rollouts pass hundreds of MB in long sessions: never load one whole, keep only the summary in the index.

## 3. Normalized model (Python 3.9)

Both readers produce the same model, in `core/agents/model.py`:

```python
from dataclasses import dataclass, field
from typing import Dict, List, Optional

PUBLISH_STATES = ("none", "committed", "pushed", "pr_open")
FILE_KINDS = ("edit", "new", "read", "delete")
COMMAND_KINDS = ("shell", "test", "publish")
EVENT_KINDS = ("user", "assistant", "command", "file")


@dataclass
class FileTouch:
    path: str            # absolute
    kind: str            # FILE_KINDS
    first_at: str = ""   # ISO
    last_at: str = ""


@dataclass
class CommandRun:
    text: str
    at: str = ""
    kind: str = "shell"  # COMMAND_KINDS
    exit_code: Optional[int] = None


@dataclass
class AgentSession:
    id: str                       # sessionId or payload.id
    agent: str                    # "claude" | "codex"
    file_path: str
    cwd: str = ""
    project_name: str = ""        # repository basename (without the worktree suffix)
    project_root: str = ""        # repository root (without the worktree folder)
    git_branch: Optional[str] = None
    worktree: Optional[str] = None
    title: Optional[str] = None
    started_at: str = ""
    last_activity_at: str = ""
    is_active: bool = False
    model: Optional[str] = None
    cli_version: Optional[str] = None
    turns: int = 0
    files: List[FileTouch] = field(default_factory=list)
    commands: List[CommandRun] = field(default_factory=list)   # last 200
    commands_total: int = 0
    published: str = "none"       # level reached since the last edit
    pr_opened: bool = False
    tokens: Optional[Dict[str, int]] = None  # input, output, cache_read, cache_write
    first_user_message: Optional[str] = None
    subagents: int = 0
    origin: str = ""              # subagent or desktop when the session does not start in a tab
    pairing_id: Optional[str] = None
    theme: Optional[str] = None
    loop_alert: Optional[Dict] = None        # {command, count, since}
    parse_errors: int = 0
    files_count: int = 0          # counts from the index's light summary
    edited_count: int = 0


@dataclass
class SessionEvent:
    at: str
    kind: str              # EVENT_KINDS
    text: str
    tool: Optional[str] = None
```

`published` is the level reached since the last file edit: editing after a commit goes back to `none`, so the trail shows what is not reconciled. `pr_opened` remembers that `gh pr create` happened; with a push after the last edit, the trail shows a PR.

## 4. Adding an agent

Today the app reads only Claude Code and Codex. A new reader needs:

- `new_session(path)` and a class with `feed(obj)` and `state()`, as in `core/agents/claude_reader.py`, registered in `_readers()` in `core/agents/reading.py`. `state()` keeps what is needed to continue from the offset. `drain_usage()` is optional and delivers the usage rows.
- File discovery in `core/agents/discovery.py` and in `AgentWatcher.files()`, in `core/agents/watcher.py`.
- Tool effects as data in `core/agents/rules.py`.
- The name in `AGENTS`, in `core/agents/model.py`, and the resume command in `RESUME_COMMANDS`, in `server/agents_api.py`.

The tests use the samples in `tests/fixtures/agents/`. See [testing.md](testing.md).
